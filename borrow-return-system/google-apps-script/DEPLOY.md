# คู่มือ Deploy ระบบยืม-คืนสินค้า (Google Apps Script + GitHub Pages)

ระบบนี้ประกอบด้วยไฟล์ 2 ไฟล์เท่านั้น:
- `Code.gs` — Backend (Google Apps Script Web App + Google Sheets เป็นฐานข้อมูล)
- `index.html` — Frontend (HTML + CSS + JS ไฟล์เดียว โฮสต์บน GitHub Pages)

---

## ขั้นตอนที่ 1: สร้าง Google Sheet (ฐานข้อมูล)

1. ไปที่ https://sheets.google.com สร้างสเปรดชีตใหม่ ตั้งชื่อ เช่น `ระบบยืม-คืนสินค้า DB`
2. เปิดเมนู **ส่วนขยาย (Extensions) > Apps Script**
3. จะเปิดหน้าต่าง Apps Script Editor ที่ผูกกับสเปรดชีตนี้ (Container-bound script)

## ขั้นตอนที่ 2: ใส่สคริปต์ Code.gs

1. ในหน้า Apps Script ให้ลบโค้ดเริ่มต้นในไฟล์ `Code.gs` ออกทั้งหมด
2. คัดลอกโค้ดทั้งหมดจากไฟล์ `google-apps-script/Code.gs` ของโปรเจกต์นี้ แล้ววางแทน
3. กด **บันทึก** (ไอคอนแผ่นดิสก์ หรือ Ctrl+S)

## ขั้นตอนที่ 3: รัน setupSheets() ครั้งแรก

1. ที่แถบด้านบนของ Apps Script Editor เลือกฟังก์ชัน `setupSheets` จาก dropdown (ข้าง ▶ Run)
2. กด **Run** (▶)
3. ครั้งแรกระบบจะขอ **อนุมัติสิทธิ์ (Authorize)** — เลือกบัญชี Google ของคุณ แล้วกด "Advanced" > "Go to (ชื่อโปรเจกต์) (unsafe)" > Allow
   (ขึ้นคำเตือนเพราะเป็นสคริปต์ที่คุณเขียนเอง ไม่ได้ผ่านการตรวจสอบของ Google ซึ่งปลอดภัยสำหรับการใช้งานของคุณเอง)
4. ตรวจสอบที่สเปรดชีตว่ามีการสร้างชีต `Products`, `Partners`, `Transactions`, `Settings`, `Users`, `ActivityLogs` พร้อมข้อมูลตัวอย่างแล้ว
5. ชีต `Users` จะมีบัญชีเริ่มต้น **admin@example.com / Admin@1234** (ระบบจะบังคับให้เปลี่ยนรหัสผ่านทันทีที่ล็อกอินครั้งแรก)

> หากลืมรันขั้นตอนนี้ ระบบจะเรียก `setupSheets()` ให้อัตโนมัติเมื่อพบว่าชีตที่จำเป็นขาดหายไปตอนเรียก API ครั้งแรก

## ขั้นตอนที่ 4: Deploy เป็น Web App

1. ที่มุมบนขวาของ Apps Script Editor กด **Deploy > New deployment**
2. กดไอคอนรูปเฟือง ⚙ เลือกประเภท **Web app**
3. ตั้งค่า:
   - Description: `ระบบยืม-คืนสินค้า API v1`
   - Execute as: **Me (บัญชีของคุณ)**
   - Who has access: **Anyone**
4. กด **Deploy**
5. ระบบจะขออนุมัติสิทธิ์อีกครั้ง (ถ้ายังไม่เคยอนุมัติ) ให้กด Authorize access ตามขั้นตอนที่ 3
6. คัดลอก **Web app URL** ที่ได้ (รูปแบบ `https://script.google.com/macros/s/XXXXXXXXXXXX/exec`)

> ทุกครั้งที่แก้ไขโค้ด `Code.gs` ต้องกด **Deploy > Manage deployments > แก้ไข (ไอคอนดินสอ) > New version > Deploy** เพื่อให้ URL เดิมใช้โค้ดเวอร์ชันล่าสุด

## ขั้นตอนที่ 5: ใส่ API_URL ในไฟล์ index.html

1. เปิดไฟล์ `google-apps-script/index.html`
2. ค้นหาบรรทัด:
   ```js
   const API_URL = "https://script.google.com/macros/s/REPLACE_WITH_YOUR_DEPLOYMENT_ID/exec";
   ```
3. แทนที่ด้วย Web app URL ที่ได้จากขั้นตอนที่ 4
4. บันทึกไฟล์

## ขั้นตอนที่ 6: อัปโหลดขึ้น GitHub Pages

1. สร้าง repository ใหม่บน GitHub เช่น `loan-return-system`
2. อัปโหลดไฟล์ `index.html` (ไฟล์เดียว) ไว้ที่ root ของ repository
   - ผ่านเว็บ: กด **Add file > Upload files** แล้วลาก index.html ขึ้นไป หรือ
   - ผ่าน Git: `git add index.html && git commit -m "deploy" && git push`
3. ไปที่ **Settings > Pages**
4. ที่ **Source** เลือก branch `main` และโฟลเดอร์ `/ (root)` แล้วกด **Save**
5. รอสักครู่ GitHub จะให้ URL เช่น `https://<username>.github.io/loan-return-system/`
6. เปิด URL นี้บนมือถือ/คอมพิวเตอร์เพื่อทดสอบใช้งานระบบ

## ขั้นตอนที่ 7: ทดสอบระบบ

1. เปิดเว็บไซต์ กรอก `admin@example.com` / `Admin@1234`
2. ระบบจะบังคับให้เปลี่ยนรหัสผ่านทันที — ตั้งรหัสผ่านใหม่อย่างน้อย 8 ตัวอักษร
3. ไปที่เมนู **ตั้งค่า > ผู้ใช้งาน** เพื่อสร้างบัญชี staff/salesperson/manager ตามต้องการ
4. ไปที่เมนู **สแกน/บันทึก** ทดสอบอนุญาตสิทธิ์กล้อง แล้วลองพิมพ์รหัส `P001` ในช่อง "รหัสสินค้า" กด "ตรวจสอบ" (หรือสร้าง QR จาก `https://quickchart.io/qr?text=P001` มาสแกนจริง)
5. กรอกฟอร์ม บันทึกข้อมูล แล้วกด "พิมพ์ใบยืม/คืน (PDF)" เพื่อทดสอบการสร้าง PDF

### การทดสอบฟอนต์ภาษาไทยในใบ PDF
เนื่องจาก PDF Engine ของ Google Apps Script (แปลงจาก HtmlService) อ้างอิงฟอนต์ตามที่เครื่อง render ของ Google รองรับ ให้ทดสอบดังนี้:
1. สร้างและพิมพ์ใบ PDF อย่างน้อย 1 ใบ แล้วเปิดไฟล์ PDF ที่ได้
2. ตรวจสอบว่าตัวอักษรไทยในหัวใบ/ตาราง/ช่องเซ็นชื่อแสดงผลถูกต้อง ไม่เป็นสี่เหลี่ยม (☐) หรือภาษาอื่นทับซ้อน
3. หากพบปัญหาตัวอักษรไทยไม่แสดงผล ให้ลองสลับลำดับ font-family ใน `buildPdfHtmlTemplate()` ภายใน `Code.gs` เช่นสลับ `'Noto Sans Thai'` ขึ้นก่อน `'Sarabun'` หรือเพิ่ม `'Angsana New','Browallia New'` ต่อท้าย เพื่อให้ตรงกับฟอนต์ระบบที่ตัว render รองรับ แล้ว Deploy เวอร์ชันใหม่อีกครั้ง
4. แนะนำให้ทดสอบทั้งข้อความสั้น (ชื่อบริษัท) และยาว (หมายเหตุ/ชื่อสินค้าภาษาไทยยาวๆ) เพื่อให้มั่นใจว่าไม่มีตัวอักษรตกหล่น

## ขั้นตอนที่ 8 (แนะนำ): เปิดใช้งานแจ้งเตือนอัตโนมัติ

1. ล็อกอินด้วยบัญชี admin ไปที่เมนู **ตั้งค่า > แจ้งเตือน**
2. กรอก LINE Channel Access Token + userId/groupId, Telegram Bot Token + Chat ID, และ/หรืออีเมลผู้รับแจ้งเตือน
3. กด "ทดสอบ LINE / Telegram / Email" เพื่อตรวจสอบว่าตั้งค่าถูกต้อง
4. ติ๊กเลือกความถี่ที่ต้องการ (รายวัน/รายสัปดาห์/รายเดือน/สต็อกต่ำ) แล้วกด "บันทึกการตั้งค่า"
5. กด "เปิดใช้งานแจ้งเตือนอัตโนมัติ (Trigger)" เพื่อให้ระบบสร้าง Time-driven Trigger ใน Apps Script อัตโนมัติ
   (สามารถตรวจสอบ/ลบ Trigger ได้ที่เมนู **Triggers (นาฬิกา)** ด้านซ้ายของ Apps Script Editor)

## หมายเหตุด้านความปลอดภัยและข้อจำกัด

- Session token เก็บใน `CacheService` (อายุ 1 ชั่วโมง) และฝั่ง client เก็บใน JavaScript variable เท่านั้น (ไม่ใช้ localStorage/sessionStorage) — หาก refresh หน้าเว็บจะต้องล็อกอินใหม่ตามข้อกำหนดด้านความปลอดภัย
- พยายามเข้าสู่ระบบผิดครบ 5 ครั้งจะถูกล็อกบัญชี 15 นาทีโดยอัตโนมัติ
- รหัสผ่านถูกเก็บแบบ SHA-256 + salt เฉพาะผู้ใช้ + key stretching 1000 รอบ (ไม่ใช่ plain text)
- ลืมรหัสผ่าน: ระบบจะส่งรหัสยืนยันไปทางอีเมลเท่านั้น (ไม่แสดงบนหน้าจอ) อายุ 1 ชั่วโมง
- เนื่องจากข้อจำกัด "ไฟล์เดียวเท่านั้น" (ห้ามมีไฟล์ .js/.css/manifest แยก) ระบบจึงไม่ได้ลงทะเบียน Service Worker แยกไฟล์ (ข้อจำกัดทางเทคนิคของเบราว์เซอร์ไม่อนุญาตให้ลงทะเบียน Service Worker จาก Blob URL ข้าม origin) ทำให้ระบบรองรับ "Add to Home Screen" และ manifest แบบไดนามิกได้ แต่ยังไม่ใช่ PWA ที่ใช้งานออฟไลน์แบบเต็มรูปแบบ หากต้องการออฟไลน์เต็มรูปแบบ แนะนำให้เพิ่มไฟล์ `sw.js` แยกต่างหากบน GitHub Pages ภายหลัง
- หากต้องการเปลี่ยนโลโก้/ชื่อบริษัท ไปที่เมนู **ตั้งค่า > บริษัท/โลโก้** (ต้องเป็น URL รูปภาพที่เข้าถึงได้แบบสาธารณะ)

Deploy Stockly ทีละขั้นตอน

ใช้เพียง 2 ไฟล์: Code.gs ฝั่งเซิร์ฟเวอร์ และ index.html ฝั่ง GitHub Pages

1. สร้าง Google Sheets และ Apps Script

  1. สร้าง Google Sheets ใหม่ ตั้งชื่อ เช่น Stockly Database และจำกัดสิทธิ์ชีตเฉพาะเจ้าของหรือผู้ดูแล ไม่แชร์แบบสาธารณะ
  2. เปิด Extensions > Apps Script แล้วแทนที่เนื้อหา Code.gs ด้วยไฟล์ Code.gs ที่ให้มา
  3. ถ้าใช้สคริปต์ที่ไม่ผูกกับชีต ให้กำหนด CONFIG.SPREADSHEET_ID จาก URL ระหว่าง /d/ และ /edit
  4. ตั้ง Project Settings > Time zone เป็น Asia/Bangkok แล้วกด Save

2. รัน setupSheets และอนุญาตสิทธิ์

  1. เลือกฟังก์ชัน setupSheets แล้วกด Run ใช้บัญชีที่เป็นเจ้าของฐานข้อมูล
  2. อนุญาตสิทธิ์ Google Sheets, ส่ง Email และเชื่อมต่อบริการภายนอก หากพบคำเตือนแอปยังไม่ยืนยัน ให้ดำเนินการต่อเฉพาะเมื่อเป็นสคริปต์ของตนเองและได้ตรวจโค้ดแล้ว
  3. ระบบสร้าง Products, Partners, Transactions, Settings และ Users พร้อมสินค้าและคู่ค้าตัวอย่างอย่างละ 5 รายการ และชีต Requests ที่ซ่อนไว้สำหรับป้องกัน retry ซ้ำ อย่าลบหรือแก้ไขชีตระบบนี้
  4. รหัสสินค้าสำหรับทดสอบ: P001 ถึง P005 คู่ค้าผู้ค้า V001-V003 และลูกค้า C001-C002 ข้อมูลจริงให้เพิ่มใน Products / Partners โดยตั้งคอลัมน์รหัสเป็น Plain text เพื่อรักษาเลขศูนย์นำหน้า

3. Deploy เป็น Web App

  1. กด Deploy > New deployment > Select type > Web app
  2. Execute as เลือก Me และ Who has access เลือก Anyone ไม่ใช่ Anyone with Google account
  3. กด Deploy แล้วคัดลอก URL ที่ลงท้ายด้วย /exec ห้ามใช้ /dev
  4. ทดสอบเปิด URL ตามด้วย ?action=health ต้องเห็น JSON ที่มี success: true หากองค์กรไม่อนุญาต Anyone ต้องให้ผู้ดูแล Workspace เปลี่ยนนโยบาย หรือเปลี่ยนสถาปัตยกรรม ไม่สามารถแก้ด้วย frontend ได้
  5. เมื่อแก้ Code.gs ภายหลัง ใช้ Deploy > Manage deployments > Edit > Version: New version > Deploy เพื่อคง URL เดิม

4. ตั้ง API_URL และโลโก้

  1. เปิด index.html ค้นหาตัวแปร API_URL ที่ต้นสคริปต์ของแอป แล้วใส่ URL /exec จากข้อก่อน
  2. ใส่ URL รูป HTTPS ใน LOGO_URL ได้ตามต้องการ ถ้าเว้นว่างจะใช้โลโก้ Stockly
  3. อย่าใส่ LINE token, Telegram token, รหัสผ่าน หรือข้อมูลลับลงใน HTML หรือ repository การตั้งค่าลับให้ทำผ่านหน้าตั้งค่าเมื่อเข้าสู่ระบบแล้วเท่านั้น

5. อัปขึ้น GitHub Pages

  1. สร้าง GitHub repository แล้วอัปโหลดเฉพาะ index.html ไว้ที่ root ไม่ต้องนำ Code.gs ไปโฮสต์บน GitHub Pages
  2. ไปที่ Settings > Pages > Build and deployment > Deploy from a branch
  3. เลือก branch main และ /(root) แล้วกด Save รอ GitHub แสดง URL เว็บไซต์
  4. เปิดเว็บไซต์ด้วย HTTPS บน Chrome Android อนุญาตสิทธิ์กล้อง และเลือกใช้กล้องหลัง ไม่เปิดผ่าน file:// หรือ browser ภายใน LINE

6. เข้าใช้งานครั้งแรกและทดสอบครบวงจร

  1. เข้าสู่ระบบด้วย admin@system.local / Admin@1234 ระบบบังคับเปลี่ยนรหัสผ่านทันที ไม่อนุญาตให้ใช้งานรายการอื่นก่อนเปลี่ยน
  2. ตั้งรหัสผ่านใหม่อย่างน้อย 12 ตัวอักษร มีตัวพิมพ์ใหญ่ ตัวพิมพ์เล็ก ตัวเลข และสัญลักษณ์ จากนั้นไป ตั้งค่า > บัญชีของฉัน เปลี่ยนอีเมลเริ่มต้นเป็นอีเมลจริงเพื่อให้รีเซ็ตรหัสผ่านได้
  3. สแกน Code 128 / QR ของ P001 หรือพิมพ์รหัส เลือกรับเข้า จำนวน 10 เอกสาร TEST-001 และคู่ค้า V001 แล้วบันทึก ตรวจสอบแถวใหม่ใน Transactions
  4. ลองรหัสที่ไม่มีจริง ต้องไม่แสดงฟอร์ม ลองจำนวน 0 หรือเว้นเอกสาร ต้องบันทึกไม่ได้ และปุ่มบันทึกต้องกดซ้ำไม่ได้ระหว่างรอ
  5. เปิดหน้าค้นหา Dashboard และทดสอบกรองวันที่ ตรวจยอดรวมแยกหน่วย และเลือกซ่อน/แสดง widget
  6. ลงทะเบียนผู้ใช้ใหม่ แล้วใช้ Admin อนุมัติใน ตั้งค่า > จัดการผู้ใช้ ทดสอบล็อกบัญชีด้วยรหัสผิด 5 ครั้ง และรีเซ็ตรหัสผ่านผ่านอีเมลจริง

7. ตั้งค่าแจ้งเตือน

  1. LINE: เปิดใช้งาน Messaging API สำหรับ LINE Official Account ออก Channel Access Token แล้วกรอก token และ userId/groupId ที่ได้จาก LINE Developers / webhook ผู้รับต้องเป็นเพื่อนหรือมี bot อยู่ในกลุ่ม การส่ง Push Message ขึ้นอยู่กับแพ็กเกจและโควตา LINE
  2. Telegram: สร้าง bot ผ่าน @BotFather รับ token ส่ง /start ให้ bot แล้วใช้ chat_id ของตนหรือกลุ่มที่เพิ่ม bot แล้ว
  3. Email: กรอกอีเมลผู้รับ คั่นด้วยจุลภาค ข้อความส่งผ่าน MailApp ในนามเจ้าของ Apps Script และมีโควตารายวัน
  4. กดบันทึกการตั้งค่าก่อนทดสอบแต่ละช่องทาง รออย่างน้อย 30 วินาทีระหว่างการทดสอบเพื่อป้องกัน spam จากนั้นเปิดสวิตช์แจ้งเตือนอัตโนมัติหากต้องการ
  5. Secret เก็บใน Script Properties ค่าทั่วไปเก็บใน Settings ชีต จำกัดสิทธิ์ Apps Script project เพราะ editor สามารถเข้าถึง secret ได้

ข้อจำกัดและความปลอดภัยที่ควรทราบ

CacheService จำกัด TTL สูงสุด 6 ชั่วโมง ไม่สามารถตั้ง 8 ชั่วโมงได้ตรงตามข้อกำหนด ระบบนี้ใช้อายุ session รวม 8 ชั่วโมง โดยเก็บทะเบียน session แบบใช้ hash ของ token ใน Script Properties และกู้ cache เมื่อจำเป็น ตรวจทั้งทะเบียน cache และสถานะผู้ใช้ทุกคำขอ Logout ลบทั้ง cache และทะเบียน รหัสผ่านที่เปลี่ยนหรือบัญชีที่ถูกระงับจะยกเลิกเซสชันเดิม

Frontend ใช้ fetch แบบ POST พร้อม Content-Type: text/plain;charset=UTF-8, credentials: omit และ redirect: follow ไม่ใช้ google.script.run เพราะใช้ไม่ได้บน GitHub Pages ส่ง sessionToken ใน JSON ทุกคำขอที่ต้องเข้าสู่ระบบ ห้ามเปลี่ยนเป็น no-cors เพราะจะอ่าน JSON ไม่ได้ การเลี่ยง preflight ไม่ได้ข้ามนโยบาย CORS ของ Google หาก browser อ่าน response ไม่ได้ ให้ตรวจว่า deploy เป็น Anyone ใช้ /exec และบัญชีองค์กรอนุญาต

Token เก็บในตัวแปร JavaScript เท่านั้น รีโหลดหรือปิดแท็บต้องล็อกอินใหม่ localStorage ใช้เฉพาะการเลือก widget Dashboard ไม่เก็บ token / รหัสผ่าน / notification secret

แอนิเมชันใช้ CSS เท่านั้น Chart.js ตั้ง animation: false; canvas ใช้เฉพาะวาดกราฟข้อมูล และ html5-qrcode อาจใช้ canvas ภายในสำหรับถอดรหัส หากต้องห้าม canvas ทุกกรณีจะไม่สามารถใช้สองไลบรารีนี้ตามข้อกำหนดได้

ระบบล็อตหมดอายุใช้ FEFO เมื่อส่งออกไม่ระบุวันหมดอายุ และไม่ปฏิเสธสต๊อกติดลบ ควรนำยอดยกมาเข้าระบบก่อนเริ่มใช้งาน ผลรวมหลายหน่วยไม่ใช่มูลค่าหรือยอดคงคลัง รายงานจำกัด 20,000 แถว Google Sheets, Script Properties, CacheService, Email และ UrlFetch มีโควตา เหมาะกับงานปริมาณไม่สูง ควรสำรองข้อมูล ทดสอบสิทธิ์และโควตาก่อนใช้งานจริง

ป้องกันกดซ้ำและ retry ด้วย requestId เดิมภายใน 24 ชั่วโมง หากเกิด WRITE_CONFLICT ห้ามกดบันทึกใหม่โดยไม่ตรวจชีตก่อน ไม่ควรแทรก ลบ หรือเรียงแถว Transactions ขณะที่ระบบกำลังบันทึก

ควรเปลี่ยนรหัสผ่าน admin เริ่มต้นและอีเมลทันทีหลัง Deploy จำกัดผู้แก้ไขชีต / สคริปต์ และใช้บัญชีเจ้าของเฉพาะระบบนี้ Web App แบบ Anyone มีความเสี่ยงด้านโควตาและการโจมตีสาธารณะ สำหรับงานสำคัญควรใช้ gateway ที่มี rate limiting และระบบยืนยันตัวตนที่ผ่านการตรวจสอบเพิ่มเติม

  • Failed to fetch: ตรวจ API_URL, /exec, Anyone, สิทธิ์เจ้าของสคริปต์ และ Deploy version ใหม่ อย่าปิด CORS ด้วยส่วนขยาย และอย่าใช้ JSONP ส่งข้อมูลส่วนตัว
  • รีเซ็ตไม่ได้: เปลี่ยนอีเมล admin@system.local เป็นอีเมลจริง ตรวจ spam และโควตา MailApp รหัสรีเซ็ตจะไม่แสดงบนหน้าเว็บ
  • หน้าเว็บยังเป็นโหมดทดลอง: API_URL ยังว่าง หรือ browser ใช้ไฟล์เก่า ลอง refresh แบบไม่ใช้ cache
  • แจ้งเตือนล้มเหลวแต่บันทึกสำเร็จ: รายการถูกเก็บแล้ว ไม่ต้องบันทึกซ้ำ ให้แก้ token / ผู้รับ / โควตา แล้วทดสอบส่งใหม่
